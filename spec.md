# SPEC: genc — шифрование текстового файла по паролю

Учебный проект (НИТУ МИСИС, «Технологии программирования», задача 14 «Шифрование»).
Этот документ — единственный источник требований для реализации. Проектные решения уже приняты в отчёте (`docs/report/`), здесь они переведены в конкретные требования к коду. Уточнения к первоначальным схемам перечислены в `docs/DECISIONS.md`. Если SPEC и отчёт расходятся в других местах — остановись и сообщи о расхождении, не выбирай сам.

## 1. Задача

Пользователь указывает текстовый файл и вводит пароль. Программа шифрует файл, сохраняет результат на диск и позволяет восстановить исходный текст **только при правильном пароле**. При неверном пароле, повреждении или усечении файла — ошибка, и выходной файл не создаётся (ни пустой, ни частичный).

Не цели: GUI/web, потоковая обработка больших файлов, шифрование каталогов, хранение паролей, собственная реализация криптографических примитивов.

## 2. Технологии

- Go (в `go.mod` указать актуальную версию; модуль называется `genc`).
- Разрешённые зависимости: стандартная библиотека, `golang.org/x/crypto` (`argon2`, `chacha20poly1305`), `golang.org/x/term`. Других прямых зависимостей нет. Допускается транзитивная зависимость `golang.org/x/sys`.
- **Запрещено** писать собственные реализации ChaCha20, Poly1305, Argon2, HMAC и т. п. Только библиотеки.
- Целевые ОС: Linux и macOS. cgo не использовать.

## 3. Интерфейс командной строки

```
genc encrypt -in <файл> -out <файл> [-force]
genc decrypt -in <файл> -out <файл> [-force]
genc -h | genc <команда> -h
```

- Парсинг — стандартный пакет `flag`, по одному `FlagSet` на подкоманду.
- Пароль **только** интерактивно с терминала без эха (`term.ReadPassword`). Нельзя принимать пароль через аргументы, переменные окружения или файл. Если stdin не терминал — ошибка «ввод пароля требует терминал».
- При шифровании пароль запрашивается дважды. Приглашения и сообщения — в stderr, результат в `-out`. В stdout программа не печатает ни содержимое файла, ни ключ.
- Выходной файл уже существует и нет `-force` → ошибка до начала какой-либо работы. `-in` и `-out` указывают на один и тот же файл → ошибка.
- Коды возврата: `0` успех; `1` ошибка выполнения; `2` ошибка использования (неверные флаги).
- Тексты для пользователя на русском:

| Ситуация | Сообщение (stderr) |
|---|---|
| успех, encrypt | `Готово: зашифрованный файл сохранён в <out>` |
| успех, decrypt | `Готово: файл расшифрован в <out>` |
| пароль пустой | `ошибка: пароль не может быть пустым` |
| пароли не совпали | `ошибка: пароли не совпадают` |
| stdin не терминал | `ошибка: ввод пароля требует терминал` |
| out существует | `ошибка: выходной файл уже существует (используйте -force)` |
| in == out | `ошибка: входной и выходной файлы совпадают` |
| вход слишком большой | `ошибка: файл слишком большой (максимум 1 ГиБ)` |
| ошибка чтения/записи | `ошибка: не удалось прочитать файл: <причина>` / `... записать файл: <причина>` |
| формат контейнера | `ошибка: неверный формат файла` |
| тег не сошёлся | `ошибка: неверный пароль или файл повреждён` |

Неверный пароль и изменение, после которого контейнер проходит проверку формата, **намеренно** дают одно сообщение.

## 4. Криптографические решения (фиксированы)

| Что | Решение |
|---|---|
| Вывод ключа | Argon2id (`argon2.IDKey`), ключ 32 байта. Параметры по умолчанию: `t=3`, `m=65536` КиБ (64 МиБ), `p=4` |
| Соль | 16 случайных байт на каждый файл (`crypto/rand`) |
| Шифрование | ChaCha20-Poly1305 (`chacha20poly1305.New`), nonce 12 случайных байт (`crypto/rand`) |
| Связанные данные (AAD) | весь заголовок контейнера (39 байт) |
| Тег | 16 байт, добавляется библиотекой к шифртексту |
| Сравнение паролей при подтверждении | `crypto/subtle.ConstantTimeCompare` |

Обоснование для nonce: ключ уникален для каждого файла (новая соль), поэтому случайного 96-битного nonce достаточно.

## 5. Формат зашифрованного файла

Всё в порядке байт little-endian. Размер файла `S = n + 55`, где `n` — размер открытого текста.

| Смещение | Размер | Поле | Назначение |
|---|---|---|---|
| 0 | 4 | `magic` | ASCII `GENC` |
| 4 | 1 | `version` | `1` |
| 5 | 1 | `t` | число проходов Argon2id |
| 6 | 4 | `m` | память Argon2id, КиБ (uint32 LE) |
| 10 | 1 | `p` | параллелизм Argon2id |
| 11 | 16 | `salt` | соль |
| 27 | 12 | `nonce` | nonce |
| 39 | n | `ciphertext` | шифртекст |
| 39+n | 16 | `tag` | тег Poly1305 |

Заголовок = байты `[0:39]`. Дальше `ct||tag` называется `sealed` (так возвращает `aead.Seal`).

### Проверки в `unpack` (строго в этом порядке, до вывода ключа)

1. `len(blob) >= 55`, иначе `ErrTooShort`.
2. `magic == "GENC"`, иначе `ErrBadMagic`.
3. `version == 1`, иначе `ErrUnsupportedVersion`.
4. Границы параметров, иначе `ErrBadParams`: `1 <= t <= 10`; `1 <= p <= 16`; `8*p <= m <= 1048576` (1 ГиБ). Это защита от файла с огромным `m`, заставляющего занять гигабайты памяти.
5. Только после этого нарезать `salt`, `nonce`, `sealed`.

## 6. Алгоритмы

### Encrypt

1. Проверить размер входа `<= MaxInputSize` (1 ГиБ).
2. Сгенерировать `salt` (16) и `nonce` (12) из `rnd`.
3. Собрать заголовок `hdr` из параметров, `salt`, `nonce`.
4. `key = deriveKey(password, salt, params)`.
5. `sealed = seal(key, nonce, plaintext, hdr)`.
6. Затереть `key` отложенным вызовом `clear` при выходе из криптографической операции.
7. Вернуть `hdr || sealed`.

### Decrypt

1. `unpack` (проверки из п. 5; **до** запроса пароля — по схеме в отчёте).
2. `key = deriveKey(password, hdr.salt, hdr.params)`.
3. `plaintext, err = open(key, hdr.nonce, sealed, hdrBytes)`; при ошибке — `ErrAuthFailed`, открытый текст не возвращается.
4. Затереть `key`.
5. Запись результата — только после успешного шага 3.

### WriteAtomic

1. Временный файл в **том же каталоге**, что и целевой (`os.CreateTemp(dir, ".genc-*")`), права `0600`.
2. Записать все данные, `Sync`, `Close`.
3. С `-force` — `os.Rename(tmp, out)`. Без `-force` — `os.Link(tmp, out)` и удаление временного имени. Если целевой путь уже занят, `os.Link` атомарно отказывает, сохраняя существующий файл.
4. При любой ошибке — удалить временный файл. Целевой файл остаётся либо старым, либо полностью новым.

### ReadFile

Читать файл целиком в память. Отказ, если это не обычный файл или размер превышает лимит: `MaxInputSize` (1 ГиБ) при шифровании, `MaxContainerSize = MaxInputSize + 55` при расшифровании.

### Порядок работы CLI

- **encrypt:** разбор аргументов → проверки путей → чтение файла → ввод пароля ×2 → `Encrypt` → `WriteAtomic` → сообщение.
- **decrypt:** разбор аргументов → проверки путей → чтение файла → `ParseContainer` → ввод пароля → `Decrypt` → `WriteAtomic` → сообщение.

Исходный файл никогда не изменяется. Содержимое не проверяется на кодировку: шифруются байты, расшифрованный файл побайтово совпадает с исходным. Пустой файл допустим.

type Params struct { Time uint8; MemoryKiB uint32; Threads uint8 }

## 8. Ошибки

Sentinel-ошибки в `core`: `ErrTooShort`, `ErrBadMagic`, `ErrUnsupportedVersion`, `ErrBadParams`, `ErrAuthFailed`. Оборачивать через `fmt.Errorf("...: %w", err)`, проверять через `errors.Is`. CLI сопоставляет первые четыре с «неверный формат файла», `ErrAuthFailed` — с «неверный пароль или файл повреждён».

## 9. Безопасность

- Пароль и ключ хранятся только как `[]byte`; сразу после использования — `clear(...)` (через `defer`, в том числе на пути ошибки). Не превращать пароль в `string`.
- Вычисления с секретами (`deriveKey`, `seal`, `open`) выполнять внутри `secretmem.Do`. Реализация: файл с тегом `//go:build goexperiment.runtimesecret` вызывает `secret.Do` из `runtime/secret` (Go 1.26, экспериментальный), файл с `!goexperiment.runtimesecret` просто вызывает функцию. Прочитай документацию `runtime/secret` перед использованием; результаты возвращай через переменные, объявленные снаружи. Проект должен собираться и проходить тесты и с `GOEXPERIMENT=runtimesecret`, и без. Экспериментальное стирание действует на Linux amd64 и arm64. На macOS `secret.Do` вызывает функцию без экспериментального стирания.
- Не логировать пароль, ключ, соль, открытый текст.
- Не реализовывать собственных сравнений тегов: проверку выполняет библиотека.
- Временные файлы создаются с `0600` и удаляются при ошибке.

## 10. Тесты (обязательные)

Argon2id с настройками по умолчанию медленный, поэтому в тестах используй малые допустимые параметры (например `t=1, m=64, p=1`); они обязаны проходить проверки границ из п. 5.

**`core`**
- Round-trip: пустой файл, 1 байт, короткий русский текст, 1 МиБ случайных байт.
- Неверный пароль → `ErrAuthFailed`.
- Для небольшого контейнера: изменить **каждый** байт по очереди (XOR `0x01`) и убедиться, что `ParseContainer`/`Decrypt` возвращают ошибку (ни одного успеха).
- Усечь контейнер до каждой длины от 0 до `len-1` → ошибка.
- `unpack`: отдельные тесты на каждую из ошибок `ErrTooShort`, `ErrBadMagic`, `ErrUnsupportedVersion`, `ErrBadParams` (граничные значения `t`, `p`, `m`).
- Детерминированный golden-тест: фиксированные пароль, соль, nonce (через подставной `rnd`) и малые параметры дают заранее известные байты контейнера.
- Известный тестовый вектор AEAD из RFC 8439, раздел 2.8.2, для связки `seal`/`open` (скопируй вектор из RFC).
- Разные вызовы `Encrypt` для одного входа дают разные контейнеры (соль и nonce случайны).
- Fuzz: `FuzzParseContainer` (не паникует, не аллоцирует лишнего), `FuzzRoundTrip`.

**`fsio`**
- `WriteAtomic` создаёт файл с правами `0600`, не оставляет временных файлов; при сбое существующий целевой файл остаётся прежним.
- `ReadFile` отказывает на каталоге и на файле больше лимита (лимит вынести в параметр для теста).

**`cli`** (с подставным `pwd.Reader`)
- Полные сценарии encrypt → decrypt с побайтовым сравнением.
- Все сообщения и коды возврата из п. 3.
- При ошибке выходной файл не создаётся.
- Пароли не совпали; пустой пароль; `in == out`; `out` существует с и без `-force`.

Проверки запускаются из корня проекта. Команда `gofmt -l .` должна выдавать пустой список. Цели `make vet test structural fuzz` подключают тесты из раздела 5 с помощью флага `-overlay`. Цель `make test` запускает тесты с детектором гонок и с `GOEXPERIMENT=runtimesecret` отдельными прогонами.

## 12. Критерии приёмки

- Все команды проверки зелёные, с флагом `GOEXPERIMENT=runtimesecret` и без него.
- Ручной сценарий: `printf 'привет\n' > a.txt`, `genc encrypt -in a.txt -out a.genc`, `genc decrypt -in a.genc -out b.txt`, `cmp a.txt b.txt` пусто; с неверным паролем при расшифровании в ещё не существующий путь `wrong.txt` файл не появляется.
- Размер `a.genc` равен размеру `a.txt` + 55 байт.
- Зависимости только из п. 2, ни одного собственного криптопримитива.
- Поведение совпадает с отчётом; расхождения перечислены в `docs/DECISIONS.md`.
